There's many ways to play games on Pop!_OS. Popular platforms like Steam have strong Linux support, while non-steam games can be ran through a variety of launchers on Linux such as the following:

- Faugus Launcher
- Lutris
- Heroic Games Launcher
- Bottles

While this guide doesn't go over every method to play games on Pop!_OS, it does cover many of the ways you may want to play games on Pop!_OS and how the process works.

## Steam

**Steam** is a game client developed by Valve that provides access to the Steam library and store. You can use Steam to download, install, launch, and manage games on your system.

Many games include native Linux support. For Windows-only games, Steam can use **Proton**, a compatibility layer that allows many Windows games to run on Linux.

### Install Steam From the COSMIC Store

Open the **COSMIC Store** application, then either search for Steam or by clicking the **Steam (installer)** icon on the COSMIC Store home page.

The COSMIC Store indicates which version of an application can be installed and includes a dropdown list if multiple options are available. Steam has a System Package and Flatpak version available for installation. The System Package is recommended for this particular application. Verify that the System Package is selected and click the **Install** button.

![COSMIC Store Steam](./img/cosmic-store/steam.png)


Once installed, use the Applications button to search for and run **Steam**.

### Install Steam From Command Line

Open the **Terminal** application by pressing the Super Key <kbd><Icon name="fa6-brands:ubuntu" /></kbd>/<kbd><Icon name="simple-icons:popos" /></kbd>/<kbd>SUPER</kbd> and searching for _Terminal_ . 

<Aside type="tip">You can open the Terminal by simply pushing **SUPER + T** on your keyboard!</Aside>

![Application Library](./img/search-terminal.png)

Once the **Terminal** application is opened you can use the Command Line tool `apt` to search for it like so:

```bash
apt search steam
```

In the image below, we'll note that Steam has the **steam-installer** package name and the **steam** package name. **steam** is a transitional package for **steam-installer**.

![Terminal](./img/terminal-steam-search.png)

Installing **Steam** will point to **steam-installer** when you install it. Because of this, you can install either package and end up with steam installed. Either option will work.

After locating the correct application name for **Steam,** complete the install with `apt`. Type this command into the terminal and press <kbd>Enter</kbd>:

```bash
sudo apt install steam
```

<Aside type="danger" title="Important Note"> Be very careful when using sudo with ANY Command. It can make system wide changes so be sure to read everything before entering 'Y'.</Aside>

## Using Steam

Once installed, use the Applications button to search for and run **Steam**.

### Steam Play (Proton)

#### Protondb - Compatibility Reviews by the Community for games on Steam
**Proton** is a compatibility layer tool which enables support for Windows games on Linux. It's based on the **Wine** project alterations made by Valve to help overall gaming compatibility. Visit the [Protondb database](https://www.protondb.com/) to confirm if a specific game has been tested and verified working using Proton. Game compatibility is calculated into an average from community feedback for each game and assigned a medal scoring system from _Platinum_ through _Borked_.

Popular games with many reviews are seemingly reliable, but if the recent or most of the reviews are many years old, compatibility may have changed since then. It's important to read the timestamps on game scores provided by users. Some games are rated _Bronze_, _Silver_, or even _Borked_ because it previously didn't work, but now it does and hasn't been updated on ProtonDB yet. Protondb does not provide ratings for games outside of Steam.

Protondb is also a useful database on how to get games running if you are having issues with a particular title on Steam. Some users may report that you need special **launch options** or tweaks in order to get particular games to run properly. 


<Aside type="tip">It's possible to sign in to protondb with your Steam account and view your entire Steam Library and check compatibility that way.</Aside>

![protondb's Explore Page](./img/protondb-explore.png)

Proton can also be utilized outside of Steam for non-steam games. Proton Management for other applications is covered further into this article. Protondb does not provide ratings for games outside of Steam.

#### Change Default Proton Version in Steam
Proton is enabled by default on Steam so there's nothing you need to do here to start playing a game. Just click <b>Install</b> then <b>Play</b> as easily as you would in Windows to play a game on Linux.

If you'd like to manage the version of Proton that you are using as the default version across Steam as a whole, you can do so in:

<b>Steam -> Settings -> Compatibility</b> There is a dropdown for <b>"Default compatibility tool"</b> where you can change the default version of Proton as pictured below:

![Steam Settings](./img/steam/default-proton.png)

Generally we've found that **Proton Experimental** has the best results. If you need to change a Proton version for a specific game, you would do that on a per-game basis in your Steam Library instead of changing that in the Settings menu for Steam as a whole. This is covered a little further below.

## Manage Custom Proton Versions
### An Introduction to Proton Manager Tools
Valve's official Proton release may not provide optimal compatibility for specific games, or community contributors may discover improvements not yet implemented by Valve. If a game is not working with mainline or experimental versions of Proton, consider trying a community-contributed fork.

- **ProtonGE** is a popular fork created by Glorious Eggroll. Glorious Eggroll tests newer games in Proton, and often implements bug fixes ahead of Valve's official releases. You can view Glorious Eggroll's Github repo for ProtonGE [here](https://github.com/GloriousEggroll/proton-ge-custom).

**How to Install and update Custom Proton Versions**

In order to install ProtonGE or another version of Proton, it is recommended that you use one of the following Proton management applications. You can select any of the following based on which one fits your needs best.

#### ProtonUp-Qt

ProtonUp-Qt is a community-maintained GUI tool based on AUNaseef's CLI tool. The app allows downloading Proton versions for Steam, and WINE versions for Lutris and other game launchers. It will automatically put each of these compatibility layer versions in the correct location to be found by Steam and Lutris respectively. The ProtonUp-Qt Github repository can be found [here](https://github.com/DavidoTek/ProtonUp-Qt).

![ProtonUp-Qt Interface](./img/protonup-qt-overview.png)

#### ProtonPlus

ProtonPlus is another community-maintained GUI tool that allows downloading Proton versions. It can be used instead of ProtonUp-Qt if you prefer it's interface. It allows downloading Proton versions and wrappers for various game launchers such as Steam, Lutris, and others. Much like ProtonUp-Qt, it automatically installs these in the correct location to be found by Steam and their respective launchers. The ProtonPlus Github repository can be found [here](https://github.com/Vysp3r/ProtonPlus)

![ProtonPlus Interface](./img/protonplus-overview.png)

#### Protonup

Protonup is a **command-line tool** that installs, manages, and updates ProtonGE. Protonup is written in Python and maintained by AUNaseef in the [Pypi project directory](https://pypi.org/project/protonup/).

![Protonup Interface](./img/protonup-overview.png)

## Using Faugus Launcher

Now that we have Faugus up and running, There's a few tweaks we can set depending on our preferences. By default, Faugus installs in List Interface mode, but it actually has support for a variety of modes such as **list**, **grid**, **cover**, and **carrousel** modes. The launcher supports being launched in Windowed, Maximized, and even Fullscreen view and allows you to go with a simple and clean layout or a stylized view that puts your game art first. Much like Steam, it also supports Categories to organize your library, but many of the features need to be enabled, as out of the box Faugus launches into a minimalist **List Mode** view.

### Configure Settings

The first thing you may want to do is configure your settings. This is entirely optional, but does allow you to set Faugus to work better for your needs.

To modify settings, just click the settings gear cog icon and you will be taken there.

![Faugus List Mode Access to Settings Menu](./img/faugus/Main-Settings.png)

The settings menu has a lot of options for you to tweak and modify to your liking. There is a built in Proton Manager that allows you to download different Proton versions for Faugus much like what the Proton Managers that were mentioned above allow. It also allows you to change your **Default Prefix location**, which can be thought of as the **virtualized Windows environment** that gets created for each game.

#### Proton/WINE Prefixes

Each Prefix has a **virtualized C:\ drive** which mimics a Windows directory structure for your game. This is where your game's save data will be stored as well as well as where you may need to store some mods that would go in the **AppData** directory of a Windows install. While not necessary, you can even place the files for your game inside of a prefix which effectively treats the **WINE/Proton Prefix** as both the location where your game is installed and the environment for that game all in one directory. When installing games from a setup file, this will also be where your games are installed to by default.

If you want to store the games somewhere completely separate from the prefix, you can move the game files to another location such as a second drive while still keeping your prefixes somewhere else, or even just store the entire prefix on another drive.

![Faugus Settings](./img/faugus/Settings-General.png)

On our system, we're using multiple launchers, and we like to keep them all in one, singular location. The default location that Faugus likes to create Prefixes is in **~/Faugus**, but we prefer **~/Games/Faugus**. By putting everything under a subdirectory of **Games**, we can have separate directories for Lutris, Heroic, or any other game launchers you may want to try out and have it all in one, easy to access directory. If you'd like, you can even set this to be on a different drive entirely such as **/mnt/extradrive/Games/Faugus** if you have another drive you store all your games on. Ultimately, there is no harm in leaving the default, but if you'll find yourself installing games from a installers, you will want to use a drive that has space to install games on.

<Aside type="note"> In Linux, when a **~/** is present, this is shortform for your user's home directory. In the examples above, the examples would point to **/home/system76/Games/Faugus** if your username for the computer is system76. </Aside>

#### SteamGridDB Integration

SteamGridDB is a website that features artwork for just about any game you can think of including games not on Steam. It was originally created specifically as a database of art assets for Steam when Valve added the ability to customize your library and non-steam games by adding your own artwork to Steam. It has since become popular for other launchers on Linux for grabbing artwork for games.

SteamGridDB can be viewed [here](https://www.steamgriddb.com/).

Faugus Launcher supports SteamGridDB Integration to scrape covers and banners for your games. Only **Cover** and **Carrousel** modes support Cover Art and Banner Art. Covers can be grabbed with simply an internet connection, and no API Key required, while Banners will require an API key to scrape artwork. If you have an API Key, you can freely select which Banners or Covers you want by left clicking them when adding or editing a game you've added. While Covers don't require an API Key, the Cover chosen for you will be whatever the very first one is on SteamGridDB and if you want to modify this, you'd have to manually fetch it yourself via URL or a locally saved image on your computer. Banners currently do not work without an API Key.

To add an API key, navigate to **Interface** on the top menu bar of your settings menu to tab over to the Interface menu. Click the Checkbox for **SteamGridDB** to turn it on and click the **searchglass** icon to open SteamGridDB's login page in your default web browser. You will need to log in to your Steam Account and once you have done so, you will be granted an API key from SteamGridDB which you can then copy, and paste into the **API Key** field. Doing this will unlock the ability to grab Banner Art which has a checkbox to toggle on and off on the right side. Each API key is unique to your account and should **NOT** be shared with others you don't trust. In the event that happens, you can always revoke and request a new API key from SteamGridDB.

## Using Lutris

### Configure Settings

The first thing you may want to do is configure your settings. This is entirely optional, but does allow you to set Lutris to work better for your needs.

To modify settings, just click the three vertically stacked lines icons for the **Menu Button** and click on **Preferences**

![Lutris Access to Settings Menu](./img/lutris/accessing-preferences.png)

The Lutris Settings menu allows you to make some Interface changes, enable or disable **Runners**, **Sources**, your Lutris and Steam **Accounts**,and the **Default Installation Directory**.

 A **Runner** is the method we will be running our game with. Windows games will run through Proton or Wine, while Linux games would use either the Steam, Linux, or Flatpak runners. You can install additional Runners in Preferences. 

 A **Source** is where you get the game from. This can be Steam, GOG, Battle.net, or Itch.io.

There is an **Advanced** slider which reveals further settings, but we will be ignoring that.

#### Proton/WINE Prefixes

Each Prefix has a **virtualized C:\ drive** which mimics a Windows directory structure for your game. This is where your game's save data will be stored as well as well as where you may need to store some mods that would go in the **AppData** directory of a Windows install. While not necessary, you can even place the files for your game inside of a prefix which effectively treats the WINE/Proton Prefix as both the location where your game is installed and the environment for that game all in one directory.

If you want to store the games somewhere completely separate from the prefix, you can move the game files to another location such as a second drive while still keeping your prefixes somewhere else, or even just store the entire prefix on another drive.

![Lutris Settings](./img/lutris/global-settings.png)

On our system, we're using multiple launchers, and we like to keep them all in one, singular location. The default location that Lutris likes to create Prefixes is in **~/Games**, but we prefer **~/Games/Lutris**. By putting everything under a subdirectory of Games, we can have separate directories for Faugus, Heroic, or any other game launchers you may want to try out and have it all in one, easy to access directory. If you'd like, you can even set this to be on a different drive entirely such as **/mnt/extradrive/Games/Lutris** if you have another drive you store all your games on. Ultimately, there is no harm in leaving the default, but if you find yourself primarily installing games from installers or Lutris scripts, you will want to use a drive that has space to install games. For any installation method other than manually adding it, the game is stored within the Prefix directory.

<Aside type="note"> In Linux, when a **~/** is present, this is shortform for your user's home directory. In the examples above, the examples would point to **/home/system76/Games/Lutris** if your username for the computer is system76. </Aside>

For this example, we will be installing a game manually. This usually makes sense for portable games where the game's .exe and game files are already present on the drive, but if you'd like to run a setup.exe manually, that can still be done manually as well.
